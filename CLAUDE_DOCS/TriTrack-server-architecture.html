TriTrack research server — host and network boundaries

One Linux host · seven long-running containers · two inbound TCP ports, 443 and 80 · one outbound service dependency, a mail relay

The seven containers

ContainerImageReachable fromWhat it does
proxycaddy:2-alpine Host ports 443 and 80 Terminates TLS and obtains its own certificate. Port 80 serves the ACME challenge only. The single entry point.
serverDart binary on debian:bookworm-slim The proxy container only The application: sign-in, sync, project membership. Publishes no host port — the compose file removes it explicitly. Its one outbound connection is to the mail relay, to send sign-in links.
postgrespostgres:16-alpine The other six containers The database. No host port in any configuration, so it is not reachable from the network at all.
audit-retentionSame image as server Nothing — it only makes outgoing queries Applies retention windows: a year for sign-in events, 180 days for sync traffic, 30 days for decided join requests.
backup-schedulerBuilt on postgres:16-alpine Nothing — it only makes outgoing queries One encrypted, signed database dump every 24 hours, into a directory on the host disk.
project-destructionSame image as server Nothing — it only makes outgoing queries Destroys a project on the date its owner scheduled, so no device has to be online for the deletion to happen.
tombstone-retentionSame image as server Nothing — it only makes outgoing queries Purges records deleted more than 24 months ago (measured from when this server accepted the delete), so the database does not grow without bound.

What crosses the host boundary

  • Inbound TCP 443 — field devices syncing. This is the only port anyone uses.
  • Inbound TCP 80 — reachable by Let's Encrypt for the certificate challenge, nothing else.
  • Outbound TCP 443 — the proxy renewing its certificate, roughly every 60 days.
  • Outbound SMTP — the server handing sign-in links to a mail relay, over TLS, whenever someone signs in. Port 587 with STARTTLS by default; the relay, port and sending address are configuration, and which relay is a question for NAU.
  • Nothing else. No telemetry, no package fetching at runtime.

What it stores

  • Researchers' names and email addresses.
  • Field records — coordinates, times, and radio frequencies of collared animals.
  • Sensitive in a conservation sense (locations of protected species); not FERPA, not HIPAA, no student data, no payment data.
  • Backups stay on this host. Where a second copy may live is one of our questions.
